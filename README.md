
# MAX Chat (React + GREEN-API)

Простой веб-интерфейс для обмена текстовыми сообщениями в мессенджере MAX
через сервис [GREEN-API](https://green-api.com/max).

## Стек
- React 18
- Vite
- Нативный fetch (без сторонних HTTP-клиентов)

## Функционал
- Вход по `idInstance` и `apiTokenInstance`
- Создание чата по номеру телефона получателя (с проверкой существования аккаунта)
- Отправка текстовых сообщений (метод `sendMessage`)
- Приём входящих сообщений и исходящих из консоли (методы `receiveNotification` + `deleteNotification`)
- Отображение статуса авторизации инстанса (`stateInstanceChanged`)
- Периодический опрос очереди уведомлений (long polling на 5 секунд)

## Как пользоваться
1. Получите `idInstance` и `apiTokenInstance` в личном кабинете
   [console.green-api.com](https://console.green-api.com).
2. При старте приложения автоматически вызывается `setSettings` с пустым
   `webhookUrl` — это включает режим получения уведомлений через HTTP API.
3. Введите данные, нажмите «Войти».
4. Введите номер получателя (например `79065937438`) и нажмите «+». Приложение проверит наличие аккаунта в MAX и создаст чат.
5. Отправляйте текстовые сообщения и получайте ответы.

## Используемые методы API

Все запросы отправляются на базовый URL: `https://api.green-api.com`.
Формат URL: `{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}`

### 1. SetSettings
**Назначение:** Настройка инстанса для получения уведомлений по HTTP API (очистка `webhookUrl`).
- **Метод:** `POST`
- **Тело запроса:**
  ```json
  {
    "webhookUrl": "",
    "outgoingWebhook": "yes",
    "stateWebhook": "yes",
    "incomingWebhook": "yes"
  }
  ```
- **Ответ:**
  ```json
  {
    "saveSettings": true
  }
  ```

### 2. GetStateInstance
**Назначение:** Получение текущего статуса инстанса (авторизован, заблокирован и т.д.).
- **Метод:** `GET`
- **Тело запроса:** отсутствует
- **Ответ:**
  ```json
  {
    "stateInstance": "authorized"
  }
  ```

### 3. CheckAccount
**Назначение:** Проверка существования аккаунта MAX по номеру телефона и получение его `chatId`.
- **Метод:** `POST`
- **Тело запроса:**
  ```json
  {
    "phoneNumber": 79065937438
  }
  ```
- **Ответ:**
  ```json
  {
    "exist": true,
    "chatId": "10000000"
  }
  ```

### 4. SendMessage
**Назначение:** Отправка текстового сообщения в чат.
- **Метод:** `POST`
- **Тело запроса:**
  ```json
  {
    "chatId": "10000000",
    "message": "Привет!"
  }
  ```
- **Ответ:**
  ```json
  {
    "idMessage": "1763115112345"
  }
  ```

### 5. ReceiveNotification
**Назначение:** Получение одного входящего уведомления из очереди (long polling).
- **Метод:** `GET`
- **Query-параметр:** `?receiveTimeout=5` (время ожидания в секундах)
- **Тело запроса:** отсутствует
- **Ответ (если очередь пуста):**
  ```json
  null
  ```
- **Ответ (если есть уведомление):**
  ```json
  {
    "receiptId": 1234567,
    "body": {
      "typeWebhook": "incomingMessageReceived",
      "senderData": { "chatId": "10000000" },
      "messageData": {
        "typeMessage": "textMessage",
        "textMessageData": { "textMessage": "Привет!" }
      },
      "timestamp": 1763115112
    }
  }
  ```

### 6. DeleteNotification
**Назначение:** Удаление уведомления из очереди после его обработки.
- **Метод:** `DELETE`
- **URL:** `.../deleteNotification/{receiptId}`
- **Тело запроса:** отсутствует
- **Ответ:**
  ```json
  {
    "result": true,
    "reason": ""
  }
  ```

### Формат обрабатываемых уведомлений

Приложение анализирует поле `typeWebhook` внутри `body`:
- **`incomingMessageReceived`** — входящее сообщение от собеседника. Добавляется в чат слева (серый бабл).
- **`outgoingAPIMessageReceived`** / **`outgoingMessageReceived`** — сообщение, отправленное через API (например, из Postman), либо с телефона. Добавляется в чат справа (фиолетовый бабл).
- **`stateInstanceChanged`** — изменение статуса инстанса. Обновляет бейдж в футере сайдбара.

## Примечания
- Для MAX идентификатор личного чата формируется динамически через `CheckAccount`. Отправка напрямую на `<номер>@c.us` возможна, но не рекомендуется.
- Если `receiveNotification` возвращает `null` — это нормально, значит очередь пуста.
- Если уведомления не приходят — убедитесь в личном кабинете GREEN-API, что поле **«Адрес отправки уведомлений (URL)»** пустое, а переключатели «Входящие сообщения» и «Сообщения от API» включены.
- Все запросы идут напрямую в `https://api.green-api.com` (CORS разрешён).
